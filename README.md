# PRD 与评审管理工具

面向产品经理、需求分析师和项目评审参与者的本地 PRD 工作台。将需求正文、表格、评审意见和历史需求集中在一份文档中，帮助团队完成需求编写、评审整理和归档交付。

基于 Electron、Vue 2 和 Element UI，主要面向 Windows x64。文档保存在本地，可通过独立文件迁移；支持桌面运行和本机浏览器预览。

## 主要功能

- **项目与多文档管理**：关联已有项目文件夹，在子目录创建 PRD，通过标签切换多份文档，也可直接打开独立文档。
- **结构化需求编写**：使用模块和数据项组织需求，编辑正文、表格、历史需求和评审记录，支持模块搜索。
- **保存与恢复**：自动保存、编辑草稿恢复、撤销与重做、回收站、文档备份与恢复，以及外部修改冲突检查。
- **原型关联**：关联网页地址或本地原型文件，随 PRD 保存关联信息。
- **评审录音**：录制、导入和管理评审音频，维护转写文本及会议纪要。
- **离线交付**：导入旧 HTML 文档，导出可在浏览器查看的只读 HTML 归档。
- **AI 协作**：通过 MCP 让兼容的 AI 客户端查询项目、读取 PRD 和提交结构化修改。
- **主题切换**：支持浅色与暗黑界面。

## 快速开始

### 从源码运行

准备 Node.js、npm 和 Windows 桌面环境，在项目目录执行：

```sh
git clone https://github.com/AnzaiDesign/prd-workspace.git
cd prd-workspace
npm ci
npm start
```

`npm start` 会准备编辑器资源并启动 Electron 桌面应用。

### 本机浏览器预览

```sh
npm run preview
```

打开终端显示的地址，默认是 `http://127.0.0.1:4173`。端口被占用时以实际输出为准，使用期间保持服务运行。预览服务仅监听本机，项目列表与最近记录保存在 `preview-data/`。

### 基本使用流程

1. 创建项目并选择已有文件夹，或直接打开 PRD 文件。
2. 新建 PRD，使用模块和数据项组织需求。
3. 编写正文和表格，记录评审意见、历史变更及原型关联。
4. 根据需要管理评审录音、转写文本和会议纪要。
5. 保存可编辑文档，或导出只读 HTML 用于离线查看。

## 文档与数据

PRD 使用 `.prdproj` 文件保存，包含正文、表格、评审、历史、回收站及编辑草稿。项目列表和最近打开记录属于本机配置。

音频及其他外部引用文件可能独立存放。迁移含附件的文档时，应一并保留相关项目目录；单独复制 PRD 文件不等于复制所有附件和备份。外部备份位于文档同目录的 `.prd-backups/` 中。

只读 HTML 包含已提交内容，交付前请先提交编辑弹窗中的草稿。当前工具以本地单人编辑为主，同一文件不支持多人同时写入。

## MCP：与 AI 客户端协作

在软件左下角打开 **MCP 接入设置**，复制生成的配置到兼容 MCP 的 AI 客户端。推荐使用软件级 `--connect` 连接；使用期间保持软件或预览服务打开，可访问软件中已添加的项目。

典型调用顺序：

1. `prd_list_projects` 获取项目 ID。
2. 使用 `projectId` 查询文件并打开文档。
3. `prd_read_document` 读取内容与 hash。
4. `prd_apply_changes` 携带读取所得 hash 提交修改。

写入保留备份、历史和冲突检查，并同步到界面。编辑弹窗、录音或加载期间可能拒绝修改，需要等待当前操作结束。

正文写入目前为普通文本。录音接口提供元数据、转写和纪要，不提供音频二进制，也不会自动完成语音转写。

详见 [MCP 接入说明](MCP入口.txt)。[配置示例](mcp.config.example.json) 展示的是兼容的 `--root` 文件模式；软件级连接请以界面生成的配置为准。

## 开发命令

| 命令 | 用途 |
| --- | --- |
| `npm ci` | 按锁定文件安装依赖 |
| `npm start` | 启动桌面应用 |
| `npm run preview` | 启动本机预览 |
| `npm test` | 运行项目测试 |
| `npm run build` | 生成 Windows x64 安装包和绿色 ZIP |
| `npm run mcp -- --root <项目目录绝对路径>` | 启动兼容的文件模式 MCP 服务 |

构建产物输出到 `releases/`。源码运行与发行包功能取决于各自版本；构建成功不代表功能验收通过。

## 项目结构

```text
desktop/
  main.js          Electron 主进程
  preload.js       桌面桥接
  renderer.js      主界面逻辑
  store.js         文档存储与恢复
  templates/       编辑器模板
  mcp/             MCP 服务与接入说明
  tests/           自动化测试
  vendor/          本地第三方界面资源
package.json       项目信息、运行和构建命令
package-lock.json  依赖锁定
```

依赖目录、发行包、预览数据、测试输出、备份、历史封存和本机 MCP 配置已通过 `.gitignore` 排除。
